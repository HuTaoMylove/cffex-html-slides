# 内容构图与 SVG 主视觉

在需要设计 SVG 主视觉、或改善整套设计节奏时使用。固定母版、颜色与字号规则见主 skill；以下是设计判断依据，不是主题到版式的映射表。

## 用表达任务选择主视觉

先判断本页需要图形完成什么工作，以及材料提供了什么对象、证据或关系，再决定是否使用 SVG。图形可以承载信息，也可以帮助识别主题、聚焦视线或建立情境；不要求每个视觉元素都变成节点或编码数据。

| 图形的作用 | 可选表达 | 判断依据 |
| --- | --- | --- |
| 建立情境或具象化概念 | 场景插画、视觉比喻、空间组合 | 对象、动作与视角应贴合内容，少量可辨识细节比无关装饰更有用；比喻不冒充实际结构 |
| 展示对象或成果 | 主体特写、样本组合、剖面、局部放大 | 保留识别特征，以尺度和裁切突出重点；示意图与实际证据有清楚区别 |
| 解释细节或突出判断 | 批注、引线、圈选、括号、图形与文字融合 | 指向明确部位或论据；有意安排视线顺序，不重复整段正文 |
| 比较或呈现数据 | 配对构图、矩阵、按数据关系选择的图表 | 共享比较维度；比例、位置、长度与数量编码有真实依据，不能用示意面积制造定量印象 |
| 表达关系或过程 | 树、分组边界、网络、流程、时间线 | 先确定连接、方向和分组的含义；只有真实顺序、流转或因果才用流程箭头 |
| 建立视觉焦点与节奏 | 几何形态、负空间、局部衬底、轮廓与层叠 | 服从信息层级，控制在品牌内容区；装饰不与关键文字争夺注意力 |

这些表达可组合使用，也可由 HTML、PNG 或文字完成。SVG 的优势是几何可控、局部可编辑和可分组动画，并不自动提升设计质量；若一句话或一张真实图片已足够清楚，直接使用。

## 借鉴成熟方案的方法

以下来源提供可迁移的方法，无需在每次制作时联网、安装工具或下载素材。按当前表达任务选取相关方法，保留 CFFEX 的品牌、字号和资产约束，不整套复制外部风格。

| 参考 | 可迁移的方法 | 适配本 skill |
| --- | --- | --- |
| [Figma 演示设计](https://www.figma.com/resource-library/presentation-ideas/) | 组合文字、图形、插画与产品画面，按叙事安排主次 | 用主视觉与局部对齐组织内容；避免把每段文字分别包进同样的框 |
| [unDraw](https://undraw.co/illustration/advanced-customization_7ms4) | 以可编辑矢量对象构成情境，支持颜色定制 | 借鉴轮廓、动作和空间层次，适配品牌配色；无需固定采用人物插画 |
| [Lucide](https://lucide.dev/) | 用一致的描边、尺寸和细节尺度建立图标系统 | 同一套演示保持统一造型语法；图标用于识别，不能替代主体构图 |
| [Datawrapper 图表选择](https://www.datawrapper.de/blog/chart-types-guide) | 根据数据需要回答的问题选择视觉编码 | 区分比较、组成、趋势和流动；没有定量依据时使用明确的定性表达 |
| [Keynote 对象动画](https://support.apple.com/en-ae/guide/keynote/tanf96d92cb6/mac) | 通过对象移动、缩放、透明度及组合动画引导注意 | 借鉴对象连续性与焦点变化，在现有转场能力内实现合适效果；不增加无关动效 |

借鉴时提取构图、形态和视觉层级的原则，再根据当前材料重新组织。不要把某个测试样例的对象、页序或成功版式写成后续任务必须采用的方案，也不为形式多样性规定图形种类、数量或轮换顺序。

整套节奏来自主视觉、重心和阅读方式的变化，连续比较允许相同骨架。统一轮廓风格、线条层级与强调方式，不必统一每页的空间结构。

## SVG 与 HTML 协作

将 SVG 用于对象轮廓、插画细节、图表几何、分组边界和连接线，用 HTML 排版标题与长标签。让两层共享一个有明确宽高的相对定位容器；SVG 用同宽高的 viewBox。按对象或图形坐标对齐 HTML 标签，避免标签悬空或引线穿字。不要分别缩放图形和标签。

- 线宽通常 2–4 个画布像素，主关系深蓝或主蓝，辅助边界淡灰蓝；金色保留给核心文字或局部节点。
- 内联 SVG 的 `defs` ID 使用页级前缀，避免跨页 marker 引用错位。图形与文字均不放在字号规则之外。
- 用 SVG `<text>` 时明确对应字体栈并验证实际命中；不要先做很小的 viewBox 再放大，让标签实际字号失控。多行标签优先 HTML。
- 纯几何且旁边已有完整解释时使用 `aria-hidden="true"`。图解独立承载信息时用 `role="img"`、唯一的 `<title>` / `<desc>` ID 和 `aria-labelledby`，或提供相邻等价文字。
- 可用分组、裁切、蒙版和层叠突出局部、组织景深或融合图文，按实际需要选择；不让滤镜或渐变模糊信息边界。引用截图时仍用 PNG，示意界面自然标明“结构示意”。

## 视觉审阅

沿用主 skill 的分组拼图检查。判断图形是否让对象更易识别、重点更易定位、证据或关系更易理解；同时检查整体造型是否协调、局部是否可读、图形是否暗示了材料未支持的信息。用图形的表达效果评价设计，不以 SVG 标签数量、图形种类或动效数量评价。

若表达任务不同的页面仍反复使用同一空间骨架，重新选择主视觉与信息组织方式；不要仅更换图标、描边或颜色。只有装饰作用的元素可以保留适量，但应退居次要层级。

## 动效搭配

页面转场通过 `.slide` 的 `data-transition` 指定，不单独接管导航。优先选择一套连贯的动效语法，例如流程页 push、层级页 lift、章节关键图 focus，其余 fade。wipe 可用于全景或有横向阅读顺序的图，不把长段落逐字揭示。

`data-reveal` 用于少量有语义顺序的分组，`data-reveal="fade"` 用于不需要移动的标签。场景或对象可整体淡入，局部批注按讲解重点出现，不把并列元素依次入场包装成执行步骤。需要描线时用 `data-reveal="draw" pathLength="1"`，不要求所有 SVG 都描线；不添加常驻流动粒子、脉冲或循环虚线。描线元素不要放在另一个 reveal 容器中，避免两层动画叠加。

所有信息在动画结束、快速反向翻页、减弱动效、静态截图和打印时保持完整。PDF 不承载动效，不能拿 PDF 作为交互验收。动画中途也检查一次主体移动与品牌位置，静态终态看不出这些问题。
